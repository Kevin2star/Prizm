================================================================
제품 컨텍스트
================================================================
스페이스(Space)는 하나의 주제/프로젝트 작업 공간이다.
참여자(Member)는 로그인 없이 닉네임+소속으로 입장한다.
결과물(Artifact)은 참여자가 올린 텍스트다.
그룹(Group)은 유사도 기준으로 묶인 결과물 집합이며, 비교 정리본을 가진다.

================================================================
엔티티 스펙 (필드명·의미 준수)
================================================================
Space
  - id: Long, PK, auto increment
  - name: 스페이스 주제 (예: "캠퍼스 개선 아이디어")
  - joinCode: 6자리 참여 코드, UNIQUE, 대문자+숫자
  - createdAt: Instant

Member
  - id: Long, PK
  - space: Space (many-to-one)
  - nickname: 닉네임
  - school: 학교
  - major: 전공
  - createdAt: Instant
  - 같은 스페이스 안에서 nickname 중복은 허용해도 된다 (해커톤 단순화)

Artifact
  - id: Long, PK
  - space: Space
  - member: Member
  - title: 제목 (필수)
  - content: 본문 (TEXT, 필수)
  - tags: JSON 배열 문자열 또는 ElementCollection. 예: ["대기시간","동선"]
  - embedding: JSON 배열 문자열. 768차원 float 벡터. 분석 전에는 null
  - group: Group (nullable, many-to-one)
  - status: ENUM { PENDING, PROCESSING, READY, FAILED }
  - createdAt: Instant
  - updatedAt: Instant

Group
  - id: Long, PK
  - space: Space
  - label: 그룹 라벨 (예: "대기시간 문제 해결")
  - commonPoints: 공통점 텍스트
  - differences: 차이점 텍스트 (항목별 "누가 / 어떤 관점으로 / 무엇을 다르게")
  - notes: 비고 (빈틈, 특이 접근, 확장 아이디어)
  - updatedAt: Instant

인덱스
  - Space.joinCode unique
  - Artifact(space_id)
  - Artifact(group_id)
  - Member(space_id)

================================================================
구현할 것
================================================================
1) 위 엔티티와 대응하는 JPA 클래스, Enum, Repository를 만든다.
2) embedding / tags는 MySQL JSON 컬럼 또는 LONGTEXT에 JSON 문자열로 저장한다.
   벡터DB는 쓰지 않는다.
3) 엔티티 간 양방향 매핑은 최소화한다. 필요한 쪽(주로 many-to-one)만 둔다.
4) 애플리케이션을 띄워 ddl-auto=update 로 테이블이 생성되는지 확인한다.
5) 간단한 패키지 구조 예:
     com.prizm.domain / com.prizm.repository / com.prizm.api / com.prizm.ai

================================================================
하지 말 것
================================================================
- REST API 컨트롤러를 이 단계에서 본격 구현하지 않는다. (다음 단계)
- Gemini 호출, 유사도 계산, WebSocket을 넣지 않는다.
- Flyway/Liquibase는 필수가 아니다. 시간 절약을 위해 ddl-auto로 충분하다.
- User, Auth, Session 테이블을 만들지 않는다.

================================================================
완료 기준
================================================================
- Space, Member, Artifact, Group 테이블이 MySQL에 생긴다.
- Repository가 컴파일되고 컨텍스트가 정상 기동한다.
- embedding을 별도 벡터 스토어가 아니라 DB 컬럼에 저장하는 설계가 코드에 반영되어 있다.
